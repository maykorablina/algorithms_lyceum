## Динамическое программирование

**Dynamic Programming (динамическое программирование)** — это концепция в алгоритмах, которая сочетает:

 -   корректность **полного перебора**
	 - Пример полного перебора: перебор всех путей в графе/всех подмножеств множества -- корректные, но максимально неэффективные алгоритмы
 -   эффективность **жадных алгоритмов**
	 - Пример жадного алгоритма: алгоритм Прима --- на каждом шаге мы берем ребро с минимальным весом и приходим к мин. остову

DP чаще всего используется в двух типах задач:

1.  **Поиск оптимального решения**  
    (минимум / максимум: стоимость, длина, количество шагов и т.д.)
    
2.  **Подсчёт количества решений**  
    (сколькими способами можно решить задачу)
    
Это не единственные типы задач, но самые распространённые.
ДП очень полезно знать и для ЕГЭ (особенно для задания 18)

### Классический пример ДП: числа Фибоначчи и лесенка
**Числа Фибоначчи** — это последовательность чисел, в которой каждое следующее число равно сумме двух предыдущих.
Формула: `F(n) = F(n-1) + F(n-2)`

 - `F(0) = 0`
 -  `F(1) = 1` 
 - `F(2) = 1` 
 - `F(3) = 2` и так далее

  Первое, что приходит на ум -- это **рекурсия**

    def fib(n):
    if n == 1 or n == 2:
        return 1
    return fib(n - 1) + fib(n - 2)

Это абсолютно правильное решение, однако есть проблема:

-   `fib(7)` вычисляется быстро
    
-   `fib(50)` вычисляется **очень медленно**
    

Причина — большое количество повторных вычислений.

**Почему так?** Многие числа считаются повторно!

Например, при вычислении `fib(5)`: `fib(3)` вычисляется **несколько раз**

-   `fib(3)` вызывается при вычислении `fib(4)`
    
-   `fib(3)` вызывается снова при вычислении `fib(5)`

Одни и те же подзадачи решаются снова и снова!

#### Решение -- **мемоизация и bottom-up подход**! 
Раз уж мы знаем, что каждое следующее число считается на основе предыдущих, то почему бы нам **не сохранять их в какой-нибудь список**, и доставать оттуда при подсчете нового числа?
А поскольку начинаем мы с меньших чисел, и не можем рассчитать число без подсчета всех предыдущих, **мы будем идти как бы снизу вверх: считать меньшие числа и запоминать их.**

Запоминание предыдущих вычислений называется ***мемоизация***, а идея начала решения с простых подзадач, постепенно переходя к более сложным -- это ***bottom-up подход***.

#### Как это реализуем? Через список!

Создадим массив из `n + 1` элементов -- используем именно такой размер, чтобы индекс был равен нужному нам числу.

В питоне, чтобы создать массив нужной длины, нужно его чем-то по дефолту заполнить. Лучше для заполнения использовать `0`.

Запишем базовые кейсы: `dp[1] = dp[2] = 1`
Все числа >2 будем считать по формуле: `dp[i] = dp[i - 1] + dp[i - 2]`
Когда пройдемся по всем числам до `n + 1` (не включая!) массив `dp` у нас будет заполнен числами фибоначчи. Мы искали `n`-е число, поэтому ответом будет `dp[n]` (или `dp[-1]`, поскольку результат -- это последний элемент массива)

    def fib(n):
    dp = [0] * (n + 1)
    dp[1] = dp[2] = 1
    if n > 2:
	    for i in range(3, n + 1):
	        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]



#### Давайте рассмотрим аналогичную задачу, но в более знакомом вам контексте
**Условие:** есть лестница из `n` ступенек.  
За один ход можно подняться:
-   на `1` ступеньку
    
-   на `2` ступеньки
 
Нужно посчитать **количество разных способов** добраться до ступеньки `n`. *Уверена, у вас была эта задача, когда вы проходили рекурсию)*

Пусть `ways(n)` — количество способов попасть на `n`.

Чтобы попасть на `n`, мы могли прийти:

-   либо с `n-1` (шаг на 1)
    
-   либо с `n-2` (шаг на 2)
    

Значит:

`ways(n) = ways(n-1) + ways(n-2)`

Базовые случаи:

-   `ways(0) = 1` -- стоим на земле: 1 способ — ничего не делать (либо 0, если мы считаем, что раз стоим на месте, значит не делаем шагов)
    
-   `ways(1) = 1` -- можем сделать только шаг на 1
- `ways(2) = 2` -- можно сразу посчитать для удобства (либо мы сразу на 2 ступеньки шагаем, либо два раза по 1-й ступеньке)

Посколько ступеньки -- это то же самое, что и числа фибоначчи, решение на ДП будет абсолютно таким же. 

### Еще один пример ДП: монетки!

## 1. Постановка задачи

Нам даны:

-   Набор номиналов монет `С ` (например `С ={1, 2, 5, 10}`)
    
-   Целевая сумма `M`
   
Есть **два варианта** этой задачи:

1.  Найти **минимальное количество монет**, чтобы получить сумму `M`
    
2.  Найти **количество способов**, которыми можно получить сумму `M`

#### Начнем с минимального количества монет
Самое простое решение -- всегда брать монету максимального номинала, не превышающего остаток (жадный алгоритм). Однако данный алгоритм работает не для любого `С `
Например:
Номиналы монет: `{1, 4, 5}`, нужно набрать сумму `13`

-   Жадный алгоритм:
    
    -   5 + 5 + 1 + 1 + 1 = **5 монет**
        
-   Оптимальный вариант:
    
    -   4 + 4 + 5 = **3 монеты**
        
Как вы уже могли догадаться, тут нужен **динамический подход**.

Для начала, определим нашу подзадачу: будем считать минимальное количество монет для суммы `m`, назовем эту задачу `minCoins(m)`
 **Базовый случай**: `minCoins(0) = 0`  (чтобы получить 0, монеты не нужны)

\[
\text{solution}(m)=\min_{c \in \text{coins}} \bigl(\text{solution}(m-c)+1\bigr)
\]
